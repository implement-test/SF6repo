# SF6 Repository — 사양

스트리트 파이터 6 캐릭터 공략 정리 사이트. 첫 캐릭터는 테리이고, 캐릭터를 계속 추가할 수 있는 구조다.
도메인: sf6repository.com (구입 예정)

## 운영 원칙

- **완전 읽기 전용.** 방문자 계정, 댓글, 제보 기능 없음.
- 관리자만 로그인한다. 로그인하면 편집 권한이 있는 항목에 수정 아이콘이 나타나고, 패널에서 편집한다.
  콤보·셋업 순서는 숫자 칸이 아니라 목록 위 '순서 변경' 창, 또는 목록의 각 카드 왼쪽 ▲ ⠿ ▼(끌어서 놓기, 자동 저장)로 바꾼다 (새 항목은 맨 아래). 필터 중에는 보이는 카드끼리 자리를 바꾸고, 비공개 항목 자리는 그대로 둔다. 순서만 바꾼 수정은 최근 수정자·변경 이력에 남기지 않는다 (0011).
- 쓰기 권한은 UI 가 아니라 **Supabase RLS** 로 막는다. 버튼 표시는 편의일 뿐이다.
- 관리자 계층 (`supabase/migrations/0004_admin_roles.sql`)

  | 역할 | 편집 | 관리자 관리 |
  |---|---|---|
  | 최고 관리자 (1명) | 전부 | 부 관리자·캐릭터 관리자 임명/수정/해임 |
  | 부 관리자 | 전부 (공통 데이터 포함) | 캐릭터 관리자만 (다른 부 관리자는 불가) |
  | 캐릭터 관리자 | 맡은 캐릭터(여러 개)의 콘텐츠. Vs 가이드는 한쪽 캐릭터라도 맡으면 가능 | 없음 |

  - 공통 데이터(캐릭터, 패치, 용어집, 셋업 상황 태그)는 최고/부 관리자만 편집
  - 자기 역할은 바꿀 수 없고, 최고 관리자는 강등·삭제할 수 없다 (DB 트리거)
  - 공개 전 검수 없음
  - 계정은 Supabase 대시보드에서 **수동 생성**하고, `/admin` 에서 이메일로 찾아 역할을 지정한다
- 작성자·수정자를 기록하고(`created_by`, `updated_by`), 방문자 화면에 표시 이름을 보여 준다.
  이름은 `author_names` 에 따로 보관해 해임된 관리자의 크레딧도 남는다.
- 모든 변경은 `change_log` 에 남는다 (트리거, 수정·삭제 불가).
  편집 패널에서 항목별 이력을 보고 과거 시점을 불러올 수 있고, `/admin` 의 '삭제된 항목'에서 복구할 수 있다.
- 다른 관리자가 먼저 저장한 항목은 덮어쓰지 않고 경고한다 (`updated_at` 비교).
- **복사하기**: 콤보·셋업 편집 패널의 '복사' 버튼으로 같은 내용의 새 항목 창을 연다 (셋업은 이어지는 콤보 연결 포함). 제목에 '(복사본)', 작성일은 오늘, 비공개로 시작하며 저장해야 만들어진다.
- 관리자 로그인은 메뉴에 없는 `/admin` 에서 한다. 내 표시 이름, 관리자 관리, 패치, 삭제된 항목도 여기서 다룬다.
  - 로그인하면 localStorage 에 표시(`sf6r:admin`)를 남기고, 이 표시가 있을 때만 Supabase 클라이언트와 편집기 코드를 불러온다 (방문자에게는 내려가지 않음).
  - 편집 폼은 `src/lib/admin/entities.ts` 의 필드 정의로 그린다. 새 콘텐츠 종류는 여기에 추가한다.
  - 비공개(`is_published = false`) 항목은 정적 페이지에 없으므로, 관리자에게만 목록 위에 따로 보여 준다.
  - 저장하면 `/api/revalidate` 가 관리자 토큰을 확인한 뒤 모든 언어의 정적 페이지를 다시 만든다.
    Cloudflare 에서 즉시 반영하려면 OpenNext 의 tag cache / queue 설정이 필요하다 (배포 단계에서 구성).
- 모든 서비스는 무료 티어로 운영한다. 도메인만 유료(광고를 붙일 때 필요).

## 기술 스택

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 |
| DB / 인증 | Supabase (회원가입 비활성화) |
| 호스팅 | Cloudflare Workers (OpenNext 어댑터). 무료 플랜에서 광고 허용 |
| 짧은 영상 | Cloudflare R2 — GIF 대신 MP4/WebM |
| 긴 영상 | YouTube (타임스탬프 링크) |
| ISR 캐시 | R2 (`open-next.config.ts`) |

- 페이지는 언어별로 정적 생성(ISR)한다. 방문자 요청이 DB 를 직접 부르지 않는다.
- Supabase 무료 프로젝트는 7일간 요청이 없으면 일시정지되므로 Cloudflare Cron 으로 주기적으로 핑한다 (배포 단계에서 구성).

## URL

- 주소에 언어를 넣지 않는다: `/terry/combos`
- 언어는 `lang` 쿠키 → 브라우저 언어 → 한국어 순으로 정하고, `next.config.ts` 의 rewrite 로 내부 경로 `/{lang}/...` 에 연결한다.
- `/en/terry/combos` 처럼 언어를 붙인 주소도 그대로 열린다.
- **퍼가기(embed)**: `/embed/setup/12`, `/embed/combo/12` — 헤더·푸터 없이 셋업·콤보 카드만 같은 디자인으로 보여 주는 단독 페이지 (검색 제외, 하단에 원본 링크). 각 카드의 '퍼가기' 버튼에서 링크와 `<iframe>` 코드(현재 카드 높이)를 복사한다.
  헤더·푸터·관리자 도구는 `app/[lang]/(site)/layout.tsx` 에 있고, embed 페이지는 `app/[lang]/embed` 에서 그것들 없이 그려진다. OG 이미지는 예정.

## 다국어

- 한국어 필수, 영어·일본어 선택. DB 에는 `{"ko": "...", "en": "...", "ja": "..."}` 로 저장.
- 번역이 없으면 한국어 원문을 보여 주고 `Not translated` 배지를 붙인다.
- 콤보 표기는 언어와 무관하므로 번역하지 않는다.

## 공통 필드

- `target_level` 대상 수준: 초급(플래티넘 이하) / 중급(다이아) / 상급(마스터 이상). 방문자가 On/Off 로 걸러 본다.
- `difficulty` 입력 난이도: 하 / 중 / 상 (대상 수준과 별개). 대상 수준과 겹쳐서 콤보·셋업 모두 쓰지 않는다 (칼럼은 기본값으로 남김).
- `patch_id` 기준 패치. 최신 패치가 아니면 "이전 패치 기준" 배지.
- `created_date` 작성일. 기본값은 오늘, 직접 바꿀 수 있다.

## 메뉴

1. 캐릭터 선택
2. 개요 (`character_overviews`, 캐릭터마다 한 건, 0016) — supercombo 위키 캐릭터 페이지 구성 참고
   - 캐릭터 소개(글, 다국어) → 장점 / 단점(두 칸, 한 줄씩) → 클래식 / 모던 차이(한 줄씩)
   - 없으면 관리자에게 '개요 작성' 버튼
3. 커맨드 리스트 (`moves`) — 분류: 기본기 / 특수기 / 타겟 콤보 / 잡기 / 드라이브 시스템 / 필살기 / 슈퍼 아츠 (이 순서, 맨 위에 바로가기)
   - 기술 카드: 이름 · 커맨드(클래식/모던) · 설명 · 영상 + 프레임 데이터(데미지 / 발생 / 지속 / 경직 / 히트 / 가드, + 는 초록 − 는 주황). 캔슬 가능 여부와 드라이브 게이지 증감은 넣지 않는다
   - 개요·커맨드 리스트에는 대상 수준/표시/조작 필터를 두지 않는다
   - 초기 데이터: `node scripts/import-ufd.mjs` 가 Ultimate Frame Data 의 커맨드·프레임을 받아 `supabase/data/ufd_moves.sql` 을 만든다 (있는 값만, 입력은 우리 표기로 변환 — 점프는 `(점프) HP`, 모으기는 `(4 모으기) 6LP`, 변환 못 한 입력은 원문). 이미 커맨드가 있는 캐릭터는 건너뛰고 비공개로 등록. 커맨드 리스트 아래에 출처 표기
   - 관리자 **표 붙여넣기**: 엑셀·시트·웹 표를 복사해 붙여 넣으면(탭, 없으면 쉼표) 첫 줄 제목으로 열을 맞추고(없으면 이름·커맨드·데미지·발생·지속·경직·히트·가드 순), 미리 보기에서 분류·포함 여부를 고른 뒤 한 번에 등록 (`src/lib/move-import.ts`). 비공개 등록 선택 가능
4. 콤보 — **시동 기본기(여러 개) + 루트** 구성. 고정 분류 없이 태그 + 필터
   - 같은 루트에 시동기를 **그룹**으로 묶어 붙인다 (`combos.starters` = `[{name, starters: [...]}]`, 예전 목록 형식은 이름 없는 그룹 하나로 읽는다). 프리셋을 불러오면 프리셋 이름의 그룹이 된다. 번호는 그룹을 넘어 이어진다. 데미지 기준 시동기는 편집 창에서 하나를 고르고(`damage_basis: true`, 고르지 않으면 첫 번째), 카드에서 강조 표시하고 "N번 시동기 기준"으로 명시한다 (프리셋에는 기준을 저장하지 않는다)
   - **시동기 프리셋** (`starter_presets`): 캐릭터별로 이름 붙인 시동기 그룹 묶음 (`starters` 는 콤보와 같은 그룹 형식, 예전 목록 형식은 이름 없는 그룹 하나). 콤보에 불러오면 그룹들이 그대로 추가되고, 이름 없는 그룹에는 프리셋 이름이 붙는다. 캐릭터 페이지 배너의 '시동기 프리셋' 버튼(편집 권한이 있는 관리자에게만 보임)으로 팝업에서 관리한다.
     콤보 편집 시 시동기 칸에서 프리셋을 불러오면 목록에 더해지고(이미 있는 시동기는 건너뜀), 직접 추가도 된다. 관리자 전용이라 방문자에게는 공개하지 않는다
   - YouTube 링크를 넣으면 카드 아래에 플레이어를 임베드한다 (youtube-nocookie, `t=` 또는 구간 시작 반영, 기본 접힘)
   - **구간 반복**: 구간 시작·끝(`1:23` 또는 초)과 반복을 켜면 IFrame API 로 끝에 닿을 때 시작으로 되돌린다 (`youtube-loop.tsx`). 방문자가 구간 밖으로 옮기면 반복을 멈추고 '다시 반복' 버튼을 보여 준다. 끝만 있고 반복이 꺼져 있으면 그 구간만 재생하고 멈춘다. 콤보·셋업·셋업 옵션 영상 모두 해당
   - 히트 상태: 노멀 / 퍼니시 카운터 / 구석 임팩트 가드 / 구석 임팩트 스턴 (여러 개)
   - 시작 위치: 거리 무관 / 필드 / 코너 근처 / 코너 / 기타 (종료 위치는 두지 않는다). 위치 필터에서 '거리 무관' 콤보는 항상 함께 보인다
   - 한 콤보에 **루트 여러 개**를 담을 수 있다. 루트마다 데미지·콤보 후 프레임·드라이브/SA 소모를 따로 적는다. 첫 번째 루트는 기존 칼럼(notation_classic …), 2번째부터는 `combos.extra_routes`(jsonb). 카드 오른쪽 수치는 루트 1이 기본이고, 다른 루트에 마우스를 올리면(휴대폰은 누르면) 그 루트로 바뀌며 마우스가 벗어나도 마지막 루트를 유지한다. 메모는 공용(`notes`)과 루트별(루트 1은 `route_note`, 나머지는 extra_routes 의 `note`)로 나뉘고, 루트별 메모는 고른 루트의 것만 보인다. 셋업 연결 등 루트 하나만 쓰는 곳은 루트 1을 쓴다
   - 수치: 데미지(고른 기준 시동기 기준), 드라이브·SA 소모, 콤보 후 프레임(텍스트, 예: `+32`, `다운 +30`)
   - 클래식/모던 표기를 따로 저장. 모던 표기가 없으면 "클래식 전용"
5. 셋업 — '상황' 태그(거리 무관 / 필드 / 코너)로 필터. 거리 무관 셋업은 어떤 위치를 골라도 함께 보인다
   - 구성: **이어지는 콤보** → 셋업 입력(공통 부분) → 설명 → **셋업을 위한 프랙티스 설정**(기본 접힘) → **옵션 1 / 2 / …**
   - 이어지는 콤보(`setup_combos`, 여러 콤보 ↔ 여러 셋업): 콤보의 루트(마무리 루트)와 콤보 후 프레임 표시. 줄 전체를 누르면 콤보 페이지의 해당 콤보로 이동
   - 프랙티스 설정(`setups.practice`): 맨 위 더미 설정 3개 — 가드(랜덤 / 가드하지 않음 / 전부 가드 / 카운트 가드), 가드 전환(실행 / 서서 가드만 / 앉아 가드만 / 랜덤), 드라이브 리버설(랜덤) — Y 버튼으로 정하는 확률: 실행하지 않음 / 가드 발동 / 일어서기 발동 각 0~10. 지정한 것만 표시.
     그 아래 표 3개 — 다운 리버설(커맨드·딜레이) / 가드 리버설(커맨드·카운트·딜레이) / 데미지 복귀 리버설(커맨드·딜레이) + 메모.
     더미는 아무 캐릭터로 하므로 **커맨드는 표기가 아니라 글자**(다국어)로 적는다. 딜레이는 프레임
   - 옵션(`setups.options`): 머리 줄(행동 표기 + 설명) + 결과별 분기 줄(히트 / 가드 / 헛침 / 기타 · 이어지는 루트 · 메모) + YouTube
   - 기본 잡기 후 상황도 '잡기 후' 셋업으로 다룬다 (연결 콤보 없이)
   - 콤보 카드에 연결된 셋업을 표시: 마우스를 올리면 텍스트 미리보기, 클릭하면 셋업 페이지의 해당 셋업으로 이동해 강조
   - 프랙티스 세팅은 따로 탭 없이 셋업 안에만 둔다 (탭은 삭제)
6. Vs 가이드 (`vs_guides`, 0014) — 내 캐릭터가 상대를 만났을 때의 공략 항목
   - 상대는 로스터 slug (`src/lib/roster.ts`, 32명). 사이트에 페이지가 없는 캐릭터도 상대가 될 수 있다
   - 상대 선택: 필터 바(대상/표시/조작) 위, Vs 탭에서만. 기본 접힘. 펼치면 분류마다 테두리로 묶음 —
     초기 로스터(가나다순) / 시즌 1 / 시즌 2 / 시즌 3 / 시즌 4(출시 순). 상대별 공략 수 표시, 주소 `?vs=slug` 로 공유
   - 이미지: 공식 사이트 캐릭터 목록의 컬러 이미지(`select_characterN_over.png`)를 그대로 불러온다. 못 불러오면 이름 카드

   - 항목: 주제, 제목, **공용 내용**, **관련 동작·대응 여러 개**(`actions` = 선택지마다 표기(클래식/모던) + 설명, 0017), 영상. 즐겨찾기·순서 변경 지원 (퍼가기는 아직 없음)

7. 용어집 — 본문에 나오는 용어에 자동 툴팁 (예정)

## 캐릭터 페이지

- 32명 전원의 페이지가 있다 (`/{slug}`, 0015). 순서·이름·분류는 `src/lib/roster.ts` 와 같다
- 상단 배너: 공식 캐릭터 페이지(넓은 화면) 첫 화면에서 맨 위 메뉴를 뺀 구간을 그대로 옮긴다 — 배경 그림(`bg_{dir}.jpg`) + 캐릭터 이미지(`{dir}.png`). 글자는 이미지가 아니라 우리 것
  - 이미지는 배너에 보이는 부분만 잘라 WebP 로 줄인 파일(`public/characters/{slug}-bg|figure|select.webp`)을 쓴다. 원본(`image-src/`, git 제외)을 두고 `node scripts/crop-banners.mjs` 를 실행하면 잘라 두고 위치값(`src/lib/banner-assets.ts`)도 만든다. 원본 67MB → 약 6.4MB (목록 카드는 흐려지지 않게 원본 해상도 유지)
  - 잘라 둔 파일이 없는 캐릭터는 공식 주소를 그대로 불러온다 (`rosterImage` / `rosterBanner`)
  - 배치는 공식 페이지에서 잰 값(`BANNER_LAYOUT`, 캐릭터별 `FIGURE`: 상자 왼쪽·위·폭·높이, 폭 대비 %, 상자 안에서 이미지는 가운데 맞춤)을 그대로 쓴다. 임의로 조절하지 않는다. 좁은 화면에서는 같은 구도를 52rem 폭으로 그려 가운데를 보여 준다
  - `characters.portrait_url` 을 넣으면 홈 목록에서는 그것이 우선
- 홈 캐릭터 목록: 공식 캐릭터 목록의 컬러 이미지

## 디자인

SF6 게임 UI 의 색과 느낌을 쓰되, 블로그가 아닌 전문 데이터 사이트처럼 보이게 한다. 토큰은 `src/app/globals.css`.

- 기본 테마는 다크(네이비 블랙). 라이트 테마도 지원
- 포인트 색: 마젠타(메인, 선택 상태) / 옐로(하이라이트, 수치) / 보라(그라데이션)
- 대상 수준 색은 랭크 색: 초급 = 플래티넘 청록, 중급 = 다이아 보라, 상급 = 마스터 금색
- 드라이브 게이지 초록 6칸, SA 게이지 3칸 (`src/components/gauges.tsx`)
- 헤드라인: Barlow Condensed / Noto Sans KR 굵은 이탤릭 (`.display`), 작은 영문 라벨 (`.eyebrow`)
- 기울어진 평행사변형 탭·버튼 (`.skew`), 사선 줄무늬 (`.stripes`), 그라데이션 띠 (`.brand-bar`)
- 모서리는 둥글리지 않는다

## 확인 필요 (관리 페이지)

콤보·셋업·커맨드·Vs 가이드·개요 중 손봐야 할 항목을 탭으로 모아, 캐릭터별로 보여 준다 (편집 권한이 있는 캐릭터만, 캐릭터·종류로 거르기).
항목마다 보기(해당 카드로 이동) / 수정.

- **이전 패치**: 기준 패치가 최신이 아니거나 비어 있는 항목. **변경 없음**(기준 패치만 최신으로), 여러 개 한 번에.
  기준 패치만 바꾼 수정은 순서 변경처럼 '최근 수정자'·변경 이력에 남기지 않는다 (0019)
- **번역 누락**: 영어·일본어가 빠진 글이 하나라도 있는 항목. 제목·내용뿐 아니라 루트 메모·셋업 옵션·Vs 선택지·장점/단점 줄까지 검사하고 EN/JA 개수 표시 (`src/lib/translation.ts`)
- **비공개**: 공개가 꺼진 항목. **공개하기**, 여러 개 한 번에

## 방문자 설정 (localStorage)

테마(라이트/다크), 콤보 표시(이미지/텍스트), 조작(클래식/모던), 대상 수준 On/Off, 즐겨찾기, 연습 체크리스트.
설정은 `<html>` 의 `data-*` 속성으로 반영하고 CSS 로 전환한다 (`src/lib/prefs.ts`, `src/app/globals.css`).

**즐겨찾기** (`src/lib/favorites.ts`, 키 `sf6r:favorites` = `{combo: [id…], setup: [id…]}`): 로그인 없이 누구나(관리자 포함) 카드 제목 줄의 ☆ 로 추가한다. 서버는 읽지 않으므로 쿠키가 아니라 localStorage 에 둔다. 따로 탭을 만들지 않고, 각 목록(콤보·셋업, 앞으로 VS 가이드)의 필터 줄에 "★ 즐겨찾기만 (N)" 토글을 두어 다른 필터와 함께 쓴다. 브라우저마다 따로 저장되고(기기 간 공유 없음), 삭제·비공개 항목의 id 는 무시한다. 여러 캐릭터를 모아 보는 페이지는 나중에 필요하면 제목 목록 형태로 추가한다.

## 콤보 표기법

콤보는 텍스트 한 줄만 저장하고, 이미지 표시는 그 텍스트를 해석해 자동으로 그린다 (`src/lib/notation`).

| 표기 | 의미 |
|---|---|
| `2MK`, `236HP` | 방향(숫자 패드) + 버튼. 5 는 생략 |
| `LP MP HP LK MK HK` | 클래식 버튼 |
| `236PP` / `214KK` | 약중강 무관 펀치/킥 2개 → 펀치/킥 아이콘 2개 |
| `→` | 연결·캔슬 (입력할 때 `->`, `>` 도 가능) |
| `MP·HP` | 타겟 콤보 (`・` 도 가능) |
| `air HP` / `counter 5HP` / `punish 2MP` | 히트 상황 (공중 / 카운터 / 퍼니시 카운터). 커맨드와 구분되는 리본 모양 배지로 표시. 상황만 따로 써도 된다 (`punish → 2MP`) |
| `delay 5HP` | 딜레이 (점선 알약 + 스톱워치 배지. 커맨드·히트 상황과 구분되는 타이밍 지시) |
| `DR` / `DRC` / `DI` | 생 드라이브 러시 / 캔슬 드라이브 러시 / 드라이브 임팩트 |
| `f.throw` / `b.throw` | 앞잡기 / 뒤잡기 (방향키 + 파란 THROW 판) |
| `66` / `44` | 앞대쉬 / 뒷대쉬 (전용 아이콘 `dir-66.svg`, 44 는 좌우 반전) |
| `L M H SP A` | 모던 버튼 (`A` = AUTO/어시스트, `A+M` 처럼 동시 입력) |
| `ANY` | 모던 임의 버튼 |
| `4` | 방향만 (뒤로 걷기 등) |
| `(벽꽝)` | 괄호 안은 메모. 조각 앞뒤에도 붙일 수 있다: `(약간 끌어서) 5HP` |
| `5HP(2)` | 몇 번째 타격인지 |

아이콘: `public/icons` (원본은 `Image_Source`).
- 방향 3 = 9 상하 반전, 7 = 9 좌우 반전, 8 = 2 상하 반전 (CSS, 파일 없음)
- 전용 아이콘이 없는 모션(236236, 22, 41236 …)은 가장 긴 모션부터 나눠 표시
- 모던 L/M/H 원본 아이콘에는 글자가 없어서 글자를 겹쳐 그린다
- DR/DRC 아이콘은 DI 아이콘과 같은 스타일로 새로 만든 SVG
- 게임 원본 아이콘을 쓰므로, 광고를 붙이기 전에 교체를 검토한다. 경로는 `src/lib/notation/icons.ts` 한 곳에서 관리
